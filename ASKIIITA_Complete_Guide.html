1. Project Overview & Motivation

1.1 What is AskIIITA?

AskIIITA is an AI-powered Retrieval-Augmented Generation (RAG) chatbot designed exclusively for IIIT Allahabad. It allows students, faculty, and prospective students to ask natural-language questions about the institute and receive accurate, contextually grounded answers sourced directly from official IIIT Allahabad documents.

💡 One-Liner Pitch

"AskIIITA is a RAG chatbot that ingests IIIT Allahabad's official PDFs into a MongoDB Atlas vector store, retrieves the most relevant chunks via cosine similarity search, and feeds them to Gemini 2.5 Flash Lite to generate accurate, grounded answers — all through a beautiful Streamlit glassmorphism UI."

1.2 Problem Statement

Students at IIIT Allahabad frequently need information about:

  • Fee structures, semester schedules, and academic calendars
  • Hostel rules, library policies, and health center details
  • Placement statistics, curriculum details, and NEP guidelines
  • Faculty information, administrative contacts, and Gymkhana details

This information is scattered across 20+ PDF documents (fee brochures, hostel manuals, placement brochures, ordinance documents, etc.) and the institute website. Students must manually search through hundreds of pages to find answers.

⚠️ The Problem

No single search interface exists to query across all official IIIT Allahabad documents. Students waste time hunting through PDFs, emails, and websites for answers that should be instant.

2.3 Vector Database – MongoDB Atlas

MongoDB Atlas is used as both the document store and vector search engine via its Atlas Vector Search feature.

Why MongoDB Atlas for Vector Search?

  • Free M0 tier: 512 MB storage — sufficient for this use case
  • Native vector search: No need for a separate Pinecone/Weaviate instance
  • Cosine similarity: The vector index uses cosine similarity for semantic matching
  • Co-located metadata: Document text, metadata (source file, page number), and embeddings all live in the same document

Vector Index Configuration:

{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 768,
      "similarity": "cosine"
    }
  ]
}

Document Schema in MongoDB:

{
  "_id": ObjectId("..."),
  "text": "The fee for B.Tech 2026 batch is...",
  "embedding": [0.012, -0.045, 0.089, ...],  // 768 floats
  "source_file": "Fee Structure B.Tech. (New Batch 2026) updated.pdf",
  "page": 2
}

2.4 LLM – Gemini 2.5 Flash Lite

The answer generation model is Gemini 2.5 Flash Lite (gemini-2.5-flash-lite), chosen for:

  • Speed: Fastest Gemini model — sub-second responses
  • Free tier: Generous free API quota for prototyping
  • Low temperature (0.2): Reduces hallucination; answers stick closely to provided context
  • Sufficient quality: For factual Q&A over retrieved context, a smaller model suffices

2.5 Embeddings – Gemini Embedding 001

The embedding model models/gemini-embedding-001 converts text into 768-dimensional dense vectors. These vectors capture semantic meaning, enabling similarity-based retrieval.

✅ Key Numbers

  • Embedding dimensions: 768
  • Similarity metric: Cosine similarity
  • Top-K retrieved chunks: 4
  • Chunk size: 3200 characters
  • Chunk overlap: 200 characters

3.2 Ingestion Pipeline (Offline) — ingest.py

The ingestion pipeline runs once (or whenever new documents are added). It follows these steps:

  1. Load environment variables from .env (MongoDB URI, Gemini API key)
  2. Discover files: Glob all *.pdf and *.txt files from ./data/
  3. Load documents: Use PyPDFLoader for PDFs and TextLoader for text files
  4. Split into chunks: RecursiveCharacterTextSplitter with separators ["\n\n", "\n", " ", ""]
  5. Tag metadata: Each chunk gets source_file metadata (the original filename)
  6. Clear existing collection: collection.delete_many({}) for a clean re-index
  7. Batch embed & upsert: Send chunks in batches of 50 to avoid Gemini rate limits
  8. Retry logic: Handles 429 RESOURCE_EXHAUSTED, DNS failures, and transient errors with exponential backoff

3.3 Query Pipeline (Runtime) — ask() function

Every user question triggers the ask(query) function which:

  1. Connects to MongoDB Atlas (with TLS, timeout settings)
  2. Creates a retriever: MongoDBAtlasVectorSearch.as_retriever(search_kwargs={"k": 4})
  3. Embeds the query: The same Gemini embedding model converts the question to a vector
  4. Vector search: Atlas finds the top-4 most similar chunks via cosine similarity
  5. Builds the prompt: Injects retrieved context + the question into the system prompt template
  6. Calls Gemini LLM: Generates a grounded answer using only the provided context
  7. Returns answer + sources: The source PDF filenames are extracted from chunk metadata

3.4 How Vector Search Works

Cosine similarity measures the angle between two vectors. Two text chunks about "B.Tech fee structure" will have vectors pointing in similar directions, yielding a cosine similarity close to 1.0.

Formula: similarity = cos(θ) = (A · B) / (|A| × |B|)

  • 1.0 = identical meaning
  • 0.0 = completely unrelated
  • -1.0 = opposite meaning (rare in practice)

5. Code Walkthrough

5.1 ingest.py – Data Ingestion Pipeline

This is the offline preprocessing script that converts raw documents into searchable vector embeddings.

Step-by-Step Breakdown:

Step 1: Environment Loading

from dotenv import load_dotenv
load_dotenv(override=True)
MONGO_URI       = os.environ["MONGO_URI"]
GEMINI_API_KEY  = os.environ["GEMINI_API_KEY"]

Uses python-dotenv to load secrets from .env. The override=True ensures the .env file takes precedence over system environment variables.

Step 2: File Discovery

if len(sys.argv) > 1:
    file_paths = sys.argv[1:]          # Single file mode
else:
    file_paths = glob.glob("data/*.pdf") + glob.glob("data/*.txt")  # All files

Supports both single-file and batch processing modes.

Step 3: Document Loading & Splitting

splitter = RecursiveCharacterTextSplitter(
    chunk_size=3200,       # Maximum characters per chunk
    chunk_overlap=200,     # Overlap between chunks for context continuity
    separators=["\n\n", "\n", " ", ""],  # Priority order for splitting
)

🧠 Why 3200 / 200?

  • chunk_size=3200: Large enough to capture full paragraphs, fee tables, and structured content without losing context. Larger than the typical 800-1000 because IIITA documents have dense tabular data.
  • chunk_overlap=200: Ensures that information at chunk boundaries isn't lost. If a sentence spans two chunks, the overlap captures it in both.
  • Separators hierarchy: Tries to split at paragraph breaks first (\n\n), then line breaks (\n), then spaces, and finally character-level as a last resort.

Step 4: Metadata Tagging

for chunk in chunks:
    chunk.metadata["source_file"] = Path(path).name

Every chunk carries its source filename for attribution in the UI.

Step 5: Batched Upsert with Retry Logic

batch_size = 50
for i in range(0, len(all_chunks), batch_size):
    batch = all_chunks[i:i + batch_size]
    while True:
        try:
            vector_store.add_documents(batch)
            break
        except Exception as e:
            if "RESOURCE_EXHAUSTED" in str(e):
                time.sleep(30)   # Rate limit: wait 30s
            elif "getaddrinfo failed" in str(e):
                time.sleep(15)   # DNS failure: wait 15s
            else:
                time.sleep(10)   # Transient error: wait 10s

⚠️ Why Batching?

The Gemini free tier has rate limits on embedding API calls. Processing 20 PDFs generates hundreds of chunks. Sending all at once would trigger 429 RESOURCE_EXHAUSTED errors. Batches of 50 with 2-second delays between successful batches stay within limits.

def ask(query: str):
    # 1. Connect to MongoDB Atlas
    client = MongoClient(MONGO_URI, tls=True, ...)
    
    # 2. Create vector store + retriever
    emb = GoogleGenerativeAIEmbeddings(model="models/gemini-embedding-001")
    vs  = MongoDBAtlasVectorSearch(collection=col, embedding=emb, index_name=ATLAS_INDEX)
    ret = vs.as_retriever(search_kwargs={"k": 4})
    
    # 3. Create LLM with low temperature
    llm = ChatGoogleGenerativeAI(model="gemini-2.5-flash-lite", temperature=0.2)
    
    # 4. Build prompt with today's date
    today = date.today().strftime("%B %d, %Y")
    prompt = ChatPromptTemplate.from_template(f"""
You are AskIIITA, a helpful assistant for IIIT Allahabad.
Today's date is {today}. Use ONLY the context below to answer.
Context: {context}
Question: {question}
Answer:""")
    
    # 5. LCEL chain: retriever → format → prompt → LLM → parse
    chain = ({"context": ret | fmt, "question": RunnablePassthrough()}
             | prompt | llm | StrOutputParser())
    
    # 6. Execute and return answer + sources
    answer = chain.invoke(query)
    return answer, sources

6. Role-Based Access Control (RBAC) & Auditing

6.1 Access Level Hierarchy & Data Mapping

AskIIITA enforces a hierarchical permission model consisting of four roles:

Access LevelAllowed User RolesDescription / Sample Documents
publicPublic, Student, Faculty, AdminAcademics calendar, Library Rules, Course Syllabus
studentStudent, Faculty, AdminB.Tech Fee structures, Hostel Manuals, Code of Conduct
facultyFaculty, AdminPrivate Faculty directory, administrative office contacts
adminAdminAdmin settings and system logs (no default docs)

6.2 JWT-Based Authentication

To verify user identities, AskIIITA implements JWT-based authentication:

  • Credentials Database: Stored securely in a MongoDB collection named users. User passwords are encrypted on creation using standard pbkdf2_hmac password hashing with salt.
  • Token Issuance: Once credentials match, the system generates a signed JSON Web Token containing the user's ID, role, and a 24-hour expiration timestamp.
  • Token Validation: On page load, Streamlit automatically checks if a token exists in the session state and decodes/verifies the signature.

6.3 MongoDB Atlas Vector Search Pre-Filtering

Unlike insecure post-filtering (where the model retrieves chunks and then filters them in memory), AskIIITA implements database-level pre-filtering inside MongoDB Atlas Vector Search: 

retriever = vector_store.as_retriever(
    search_kwargs={
        "k": 4,
        "pre_filter": {
            "access_level": {"$in": allowed_levels}
        }
    }
)

This ensures that chunks outside the user's permission range are pruned before the vector similarity comparison occurs, guaranteeing zero leakage of restricted information.

6.4 Audit Logging & Admin Panel

For security auditing, every search query is logged in the audit_logs collection in MongoDB, storing:

  • User ID & Role
  • Query Text
  • Timestamp
  • Full list of retrieved chunks (ID, source file, access level, and content snippet)

Administrators can switch the Streamlit workspace view to the Audit Logs Explorer, which displays a comprehensive history of search activities using interactive collapsible panels.

9.1 Project-Specific Questions

1 Can you describe your project in 2-3 sentences?

AskIIITA is a Retrieval-Augmented Generation (RAG) chatbot built for IIIT Allahabad. It ingests 20+ official documents (PDFs about fees, academics, placements, hostel, etc.) into a MongoDB Atlas vector store using Gemini embeddings, then at query time retrieves the top-4 most relevant chunks via cosine similarity and passes them to Gemini 2.5 Flash Lite to generate accurate, grounded answers through a beautiful Streamlit glassmorphism UI.

2 Why did you choose RAG over fine-tuning the LLM?

RAG is superior for this use case because:

  • No training required: Fine-tuning Gemini on IIITA documents would require compute resources and is not available on the free tier
  • Easy updates: When a new fee structure PDF is released, I just re-run ingest.py — no retraining needed
  • Reduced hallucination: The LLM only sees relevant context, not memorized (potentially stale) information
  • Source attribution: RAG naturally provides which document each answer came from
  • Cost: RAG uses the standard API; fine-tuning requires expensive GPU hours
3 Walk me through what happens when a user asks "What is the B.Tech fee for 2026 batch?"
  1. The user types the question in the Streamlit input box and presses Enter
  2. The question is stored in st.session_state["messages"] as a user message
  3. The ask(query) function is called inside a st.spinner("Thinking...")
  4. A MongoClient connects to Atlas; a retriever is created with k=4
  5. Gemini Embedding 001 converts "What is the B.Tech fee for 2026 batch?" into a 768-dimensional vector
  6. MongoDB Atlas Vector Search performs cosine similarity against all stored chunk embeddings
  7. The top-4 most similar chunks (likely from "Fee Structure B.Tech. (New Batch 2026) updated.pdf") are returned
  8. These chunks are concatenated and injected into the prompt template along with the question and today's date
  9. Gemini 2.5 Flash Lite generates an answer using ONLY the provided context (temperature=0.2)
  10. The answer + source filenames are displayed in the chat with a 📄 source attribution line

  • Free M0 tier: 512 MB free storage — sufficient for this project's scale
  • Single platform: Both the document store (metadata, text) and vector index live in the same database — no need to sync between two systems
  • LangChain integration: langchain-mongodb provides first-class MongoDBAtlasVectorSearch support
  • Production-ready: Atlas is a managed service with automatic scaling, backups, and monitoring
  • Unlike ChromaDB: ChromaDB is local/in-memory — not suitable for cloud deployment on Streamlit Community Cloud where the filesystem is ephemeral

9.2 RAG Architecture Questions

9 What is RAG and why is it important?

Retrieval-Augmented Generation (RAG) is an architecture that enhances LLM responses by first retrieving relevant information from an external knowledge base, then feeding that information as context to the LLM for answer generation. It's important because:

  • It grounds LLM responses in factual data, reducing hallucination
  • Knowledge can be updated without retraining the model
  • It provides source attribution for transparency
  • It works with any LLM API (no fine-tuning needed)
10 What are the key components of your RAG pipeline?
  1. Document Loader: PyPDFLoader / TextLoader (load raw documents)
  2. Text Splitter: RecursiveCharacterTextSplitter (chunk documents)
  3. Embedding Model: Gemini Embedding 001 (text → 768-dim vectors)
  4. Vector Store: MongoDB Atlas Vector Search (store & retrieve embeddings)
  5. Retriever: Similarity search with k=4 (find relevant chunks)
  6. Prompt Template: System prompt + context + question
  7. LLM: Gemini 2.5 Flash Lite (generate answer from context)
  8. Output Parser: StrOutputParser (extract text from response)
11 What is chunking and why is it necessary?

Chunking is the process of breaking large documents into smaller, semantically meaningful pieces. It's necessary because:

  • Embedding models have input limits: A 50-page PDF can't be embedded as one unit
  • Precision: Smaller chunks mean the retriever returns more focused, relevant content
  • LLM context window: The prompt (context + question) must fit within the LLM's context limit
  • Semantic coherence: Each chunk should ideally contain a single topic or concept
12 Why did you choose chunk_size=3200 and chunk_overlap=200?

chunk_size=3200: IIITA documents contain dense tabular data (fee structures, timetables) that would be split incorrectly with smaller chunks (800-1000). 3200 characters ensures complete tables and sections stay within a single chunk.

chunk_overlap=200: Ensures contextual continuity at chunk boundaries. If a sentence spans two chunks, the 200-character overlap ensures it appears in both, so the retriever can find it regardless of which chunk is matched.

13 What is RecursiveCharacterTextSplitter and how does it work?

It's a LangChain text splitter that tries to split text at natural boundaries in a priority order: ["\n\n", "\n", " ", ""]. It first tries paragraph breaks, then line breaks, then word breaks, and finally character-level splitting as a last resort. This produces semantically coherent chunks that don't break mid-sentence.

14 What does k=4 mean in your retriever and how would you tune it?

k=4 means the retriever returns the top-4 most similar chunks for each query. I chose 4 because:

  • Too few (k=1-2): Might miss relevant context spread across multiple chunks
  • Too many (k=8-10): Adds noise, increases token cost, and may confuse the LLM
  • k=4 is a sweet spot: Provides enough context for comprehensive answers without exceeding the LLM's useful context window

To tune: I'd measure answer quality across a test set with different k values and pick the one with highest relevance and lowest hallucination.

15 What is LCEL (LangChain Expression Language)?

LCEL is LangChain's declarative way to compose chains using the pipe (|) operator. In my code:

chain = ({"context": ret | fmt, "question": RunnablePassthrough()} | prompt | llm | StrOutputParser())

This reads as: "Take the query → run it through the retriever → format the docs → insert into the prompt → send to LLM → parse the output as a string." LCEL handles streaming, async, and batching automatically.

9.3 Vector Database & Embeddings Questions

16 What are embeddings and how do they enable semantic search?

Embeddings are dense numerical vector representations of text that capture semantic meaning. The key insight is that semantically similar texts produce vectors that are close together in the embedding space. So "What is the hostel fee?" and "Cost of staying in the dormitory" would have similar vectors, even though they share few common words. This enables semantic search — matching by meaning rather than keywords.

17 Why 768 dimensions? What does each dimension represent?

768 is the output dimensionality of Gemini Embedding 001. Each dimension doesn't have a human-interpretable meaning — they are learned features that collectively capture semantic relationships. 768 is a standard size (BERT-base also uses 768) that balances representational power with computational efficiency.

18 Explain cosine similarity. Why use it over Euclidean distance?

Cosine similarity measures the angle between two vectors, not their magnitude. Formula: cos(θ) = (A·B)/(|A|×|B|). Range: [-1, 1] where 1 = identical direction.

Why over Euclidean: Cosine similarity is magnitude-invariant — it only cares about direction. A short chunk and a long chunk about the same topic will have similar cosine similarity despite different vector magnitudes. Euclidean distance would penalize the length difference.

19 How does MongoDB Atlas Vector Search work internally?

Atlas Vector Search uses an Approximate Nearest Neighbor (ANN) algorithm (specifically, a graph-based approach similar to HNSW — Hierarchical Navigable Small World). When you query, it:

  1. Converts the query text to a vector using the same embedding model
  2. Uses the ANN index to quickly find approximate nearest neighbors without comparing every vector
  3. Ranks results by cosine similarity score
  4. Returns the top-k results with their metadata

This is much faster than brute-force comparison (O(n) → O(log n)).

20 What is the schema of a document stored in MongoDB Atlas?

Each chunk is stored as a MongoDB document with fields: _id (ObjectId), text (the chunk content), embedding (array of 768 floats), source or source_file (filename), and page (page number from the PDF). The vector index is built on the embedding field.

9.4 LangChain & LLM Questions

21 What is LangChain and why did you use it?

LangChain is a framework for building applications with LLMs. I used it because it provides:

  • Abstractions for document loading, splitting, embedding, and vector search
  • Composability via LCEL (pipe operator) for building RAG chains
  • Integrations with 100+ LLMs, vector stores, and tools
  • Retriever pattern that decouples the search backend from the chain logic

Without LangChain, I'd have to manually manage PDF parsing, text splitting, embedding API calls, MongoDB queries, prompt formatting, and LLM invocations — LangChain handles all this in ~40 lines.

22 What is the purpose of the system prompt and how did you design it?
You are AskIIITA, a helpful and friendly assistant for IIIT Allahabad students and faculty.
Today's date is {today}. Use this for time-aware answers.
Use ONLY the context below to answer. If info is not in context, say so honestly.
Be concise, accurate, and friendly.

Key design decisions:

  • Identity: Gives the LLM a persona ("AskIIITA") for consistent tone
  • Date awareness: Injects today's date so it can say "this event has passed"
  • Grounding instruction: "Use ONLY the context" prevents hallucination
  • Honesty instruction: "If info is not in context, say so" prevents making up answers
  • Tone: "Concise, accurate, and friendly" shapes the response style
23 Why temperature=0.2 and not 0 or 1?

Temperature controls randomness in LLM outputs. 0 = deterministic (always picks the most likely token), 1 = highly random.

  • 0.0: Too rigid — responses feel mechanical and may repeat the same phrasing
  • 0.2: Slightly creative — allows natural language variation while staying factual
  • 1.0: Too creative — increases hallucination risk for a factual Q&A system

For a RAG chatbot where accuracy matters more than creativity, 0.2 is the sweet spot.

25 What is RunnablePassthrough in your chain?

RunnablePassthrough() simply passes the input through unchanged. In the chain {"context": ret | fmt, "question": RunnablePassthrough()}, the query goes to the retriever for context AND is passed directly as the question — the same input serves dual purposes without duplication.

9.5 Frontend & Streamlit Questions

26 Why Streamlit over Flask, Django, or React?
  • Single file: The entire app (backend + frontend) is in one Python file — no separate frontend build
  • Built-in widgets: Chat messages, buttons, columns, forms, spinners — all available as Python functions
  • Free hosting: Streamlit Community Cloud provides one-click deployment from GitHub
  • Python-native: No JavaScript needed — the team only needs Python skills
  • Tradeoff: Less flexible than React for complex UIs, but for a chatbot, Streamlit is more than sufficient
27 How does Streamlit's execution model work?

Streamlit re-runs the entire script from top to bottom on every user interaction (button click, text input, etc.). This is why:

  • st.session_state is needed to persist data across reruns
  • st.rerun() forces a fresh execution after state changes
  • Heavy operations (like the RAG query) are only triggered conditionally
  • The CSS is re-injected on every run (but this is fast since it's just HTML injection)
28 How did you implement the glassmorphism UI in Streamlit?

Via st.markdown(css_string, unsafe_allow_html=True) — I inject ~260 lines of custom CSS that targets Streamlit's internal elements using their data-testid attributes. The glassmorphism effect is achieved by targeting the center column with:

background: rgba(88, 28, 220, 0.10);
border: 1.5px solid rgba(167,139,250,0.38);
backdrop-filter: blur(32px);
box-shadow: 0 0 90px rgba(139,92,246,0.18);
29 How do you handle the campus background images?

The images are converted to base64 strings at startup using base64.b64encode(file.read_bytes()) and embedded directly in CSS/HTML via data:image/jpeg;base64,{b64_string}. This avoids serving static files, which can be tricky on Streamlit Community Cloud.

30 What is st.session_state and why is it critical here?

st.session_state is Streamlit's mechanism for persisting data across script reruns. Without it, every button click would reset the chat history, selected category, and pending query. I use 6 session state variables to track: chat messages, active category, pending query, selected program/batch (for fees), and whether to show questions.

31 How do you handle the form submission and prevent double-processing?

I use st.form(key="query_form", clear_on_submit=True) which clears the input after submission. The query processing checks query = pending or prompt_input — either a quick-question button set pending_query, or the user typed in the text box. The pending_query is consumed with st.session_state.pop("pending_query", None) to prevent re-processing on the next rerun.

Currently, the system shows an error message. To improve resilience:

  • Fallback LLM: Configure a secondary LLM (e.g., OpenAI GPT-3.5) as a fallback
  • Response caching: Cache frequent Q&A pairs in Redis — serve cached answers when the API is down
  • Circuit breaker pattern: After N consecutive failures, switch to cached-only mode
  • Health check endpoint: Monitor API availability and alert before users are affected
37 What security considerations are there in this project?
  • Secrets management: API keys and MongoDB URI are in .env (gitignored) and Streamlit Secrets for deployment
  • TLS: MongoDB connection uses tls=True for encrypted communication
  • Prompt injection: A risk — a malicious user could craft queries to make the LLM ignore its instructions. Mitigation: the low temperature and "ONLY use context" instruction reduce this risk
  • Network access: MongoDB Atlas IP whitelist is set to 0.0.0.0/0 for development — in production, this should be restricted

9.7 Error Handling & Edge Cases

38 How do you handle Gemini API rate limits (429 errors)?

During ingestion (ingest.py): The script catches RESOURCE_EXHAUSTED / 429 errors and sleeps for 30 seconds before retrying. It uses an infinite retry loop with while True: try/except.

During queries (app.py): The error is caught and a user-friendly message is shown explaining that the daily quota has been exceeded and suggesting they try later or use a paid API key.

39 What happens if a PDF fails to load?

The ingestion script checks the file extension (.pdf or .txt) and skips unsupported formats with a log message. If PyPDFLoader fails on a corrupted PDF, the exception propagates and the script exits — a future improvement would be to catch per-file exceptions and continue with the remaining files.

40 How do you handle MongoDB connection failures?

The MongoClient is configured with serverSelectionTimeoutMS=30000 (30-second timeout). During ingestion, DNS failures (getaddrinfo failed) trigger a 15-second retry. In the app, connection failures are caught by the generic except Exception block and shown as an error message in the chat.

41 Why do you use tlsAllowInvalidCertificates=True?

This is a development convenience to bypass SSL certificate verification issues that commonly occur on Windows machines, Codespaces, and some corporate networks. In production, this should be False with proper certificate validation.

It would help here by ensuring the most relevant chunks appear first, especially when the initial retrieval includes partially relevant results.

Hybrid search combines vector similarity search (semantic) with traditional keyword search (BM25/TF-IDF). This helps with:

  • Exact matches: If a user asks "What is SGPA?", the keyword "SGPA" should match exactly
  • Numbers and codes: Vector search struggles with precise numerical queries

MongoDB Atlas supports hybrid search by combining vector search with text search in a single query. I'd use $search with both knnBeta and text operators.

62 How did you implement Role-Based Access Control (RBAC) in your RAG pipeline?

We mapped document chunks to specific access levels (public, student, faculty, admin) during ingestion. At query time, we extract the user's role from their JWT, map it to allowed levels, and pass this list as a database-level pre_filter to MongoDB Atlas Vector Search. This guarantees that unauthorized chunks are never returned by the vector query.

63 Why did you use pre-filtering instead of post-filtering for role-based security?

Pre-filtering filters the search space before vector comparison, ensuring that all k returned chunks are authorized. Post-filtering retrieves the nearest chunks first and then filters out restricted ones; if the top nearest matches are all restricted, the user gets zero results or insufficient context for the LLM. Pre-filtering is more secure and performant.

64 How does JWT authentication work in a serverless deployment like Vercel?

Because serverless functions are stateless, they cannot maintain server-side session memory. Instead, we sign a JSON Web Token containing the user's ID and role using a cryptographic key (stored in Vercel's environment variables). The client sends this token in the header of each API request, and the serverless endpoint verifies it statelessly on the fly.

65 What data did you record in your audit log collection and why?

We log the user ID, role, query text, timestamp, and details of all retrieved document chunks (chunk ID, source file name, access level, and content snippet). This is crucial for security compliance, monitoring data leakage, and debugging system performance.

66 How do you secure user passwords when storing them in MongoDB?

We hash passwords using Python's standard hashlib.pbkdf2_hmac key-derivation function with 100,000 iterations of SHA-256 and a cryptographically secure random salt. The salt and hash are stored in the database. Using PBKDF2 protects against brute-force attacks and rainbow table attacks.
